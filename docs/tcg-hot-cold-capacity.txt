Hot/cold TCG capacity comparison — 2026-11-11

Candidate allocator: experimental branch at dc82321e68.
Reference allocator: libretro 8684dae402, before the layout experiment.

Run from a complete checkout containing reference commit 8684dae402:
  python3 scripts/tcg-cold-capacity.py /path/to/parallel-xbox > capacity.csv
Requires a C compiler named cc. No emulator, network or game files are used.

Method
Extract the candidate's production allocator/chunk/retry functions through
its allocation test harness, and the parent's production tcg_tb_alloc via
git show. Simulate successful body/cold publication in one 8 MiB region.
Hold metadata at 256 bytes for BOTH allocators, align metadata to 64 bytes
and code publication to the target's 16-byte boundary, and retain 1024-byte
highwater margins. Sweep 49 fixed body/cold payload combinations.
Cold payload excludes metadata and includes the modeled tail/search bytes.
No claims are made about actual game distributions or the real TB size.

Finding
Once either half fills, the candidate abandons the other half's unused
space and starts another chunk. That substantially lowers capacity for
unbalanced mixes. Equal metadata deliberately isolates partition loss;
it does not penalize the candidate's extra extent record on other hosts.
The comparison therefore does not qualify that additional metadata cost.

Decision
Do not promote the fixed-split candidate unchanged. The existing 58 ROM
passes, allocator/unwind checks and split-WX exhaustion checks establish
correctness for their cases, not acceptable capacity or faster games.
The earlier noisy process-CPU medians remain unqualified. Physical gameplay
was waived for synthetic testing; that does not turn this capacity loss
into a passing result. The cold-first-play regression remains open.

Next work
Evaluate bounded reuse of the remaining chunk space, or another layout
that avoids abandoning a large free partition. Re-run this comparison,
then the allocator/unwind, small-buffer split-WX and actual-core tests.
Measure runtime capacity across real emitted mixtures before choosing a
partition policy; a different fixed ratio alone merely moves the loss.

This follow-up changes only analysis tooling/documentation. Runtime bytes
are unchanged from the already-tested experimental candidate. The branch
remains experimental and libretro is not modified by this work.

2026-11-12 implementation follow-up
The experimental allocator now subdivides the larger unused remainder
when allocation exhausts a segment at committed cursors. Segment end is
tracked independently of original chunk end. At least 16 KiB is required
before subdivision; no dynamic allocation or free-range list is used.
Failed emission still marks the original chunk full and skips all reuse:
partially written bytes are not described by committed cursors.

Re-running the same 49-mix comparison with this conservative policy:
16/16 capacity improves to 24512 blocks (-6.48% versus parent), but 16/128
still holds only 10896 (-41.80%), and 4096/256 holds 1016 (-44.18%).
This is deliberately less aggressive than the earlier offline model.
The broad capacity gate remains failed; do not promote this branch.

The ownership regression exercises 640 reused segments and 604720
disjoint metadata/body/tail publications, besides the existing 1280
boundary, 376569 allocation and 1792 retry decisions. A new required
negative control substitutes chunk end for segment end and must fail.
Runtime emitted-body/tail mixtures and failed-emission reuse remain
future work; the original noisy timing samples remain unqualified.

Body-only overflow follow-up
Body emission now tells the overflow handler that no cold tail was written.
The handler retires every hot byte through the highwater reserve and leaves
the cold allocation cursor beyond the failed TB metadata. This permits
subdivision of untouched cold space without treating attempted body bytes
as free. A fresh segment still retries with fewer guest instructions;
cold-tail and search overflow still abandon the chunk conservatively.

Eight explicit partial-body scenarios fill every attempted hot byte and
failed metadata with canaries, then verify the next allocation remains in
untouched cold space. A required mutation control retaining the failed hot
range must fail. Existing ownership and unwind tests remain required.
The 4096/16 model improves from 1016 to 1840 blocks (-3.11% vs parent),
but cold-heavy mixtures still fail capacity qualification. No runtime
speedup, acceptable overall capacity or main-branch readiness is claimed.
