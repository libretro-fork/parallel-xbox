DOAXVB sun shadows -- experimental Vulkan enhancement

Core Options > Video > DOAXVB Sun Shadows defaults to Off. The option is
registered only on Vulkan after authenticating the supported USA 1.1106
loaded executable. Other titles, modified/unknown builds and OpenGL do not
register its key. Older core-option APIs follow the same rule; this does not
rely on a frontend implementing option-hiding callbacks. Toggle application
uses existing title polling and can take about one second.

The profile validates header/certificate bounds and revision, loaded immutable
main code and authenticated D3D SetTransform/draw-seam windows. It does not
hash writable D3D state or compare a loaded image with a file hash. No game
instruction bytes, assets or checkpoints are distributed. This is a
compatibility check, not a security boundary. Verification runs once per
observed candidate-title lifetime, including when Off. Loads/reset/unload
invalidate identification. Other titles do not invoke the verifier.

Rendering and lifetime integration

Activation parks the existing FIFO worker and selects separately compiled
CPU/FIFO/render dispatch. The normal running pusher and Vulkan draw stream
contain no per-draw enhancement checks. Off allocates no shadow images,
pipelines, descriptors, marker queue or extra geometry/uniform storage, and
records no additional rendering commands. Frontend compatibility metadata
still synchronizes after frames; translation-time hook selection and the
one-time executable check are outside rendering.

CPU capture occurs at authenticated draw seams before BEGIN publication.
It copies only camera/projection/sun scalars, translating the parameter word
separately across page boundaries. The existing FIFO lock orders the bounded
marker queue; the enhanced pusher matches physical parameter addresses and
consumes markers only after dispatch. Missing, reordered, overflowing or
invalid camera markers cannot inherit a different draw's camera.

Each admitted caster records immediately after its original native draw in
the SAME native command buffer. Vertex/index/weight/UV handles, native set 0
and its vertex-uniform snapshot are synchronous lends. No vertex, index,
palette or texture payload is copied for shadows. All host-side input lends
end before another cache mutation, upload, descriptor rewind, eviction or
arena recycle. Existing native reference marks, consumed-page tracking and
submission retirement protect the GPU reads. There is no pending replay that
requires geometry snapshots or an extended guest-pointer lifetime. Each draw
appends only 160 bytes of owned enhancement constants to existing uniform
staging. Resource exhaustion skips the enhancement and rejects that map.

The native renderer resumes with its pipeline/vertex/dynamic state restored.
Receiver variants preserve native VS/GS and descriptor set 0, and multiply
lit RGB before texture combiners and fog, preserving alpha. Positions are
reconstructed from the draw's actual CMAT/viewport constants and ordered
camera, including fixed-function skinning, rather than an assumed NDC layout.
Caster pipeline keys include actual native input formats and strides even
when native pipelines use dynamic vertex input.

Two 4096-square D16 maps (~64 MiB combined) alternate. A 64-unit box is fitted
20 units along the view ray, with 120 units of light depth and texel-snapped
XY. Current draws populate one map; receivers sample the preceding completed
scene's map with 25-tap comparison filtering and edge fading. One frame of
shadow latency is intentional. Cuts, projection changes, missing/incomplete
scenes, state loads, reset, unload and toggles invalidate temporal visibility.
Lit models use a half-unit comparison offset toward the sun and a wider
filter, following the native-port experiment's occluder-only treatment to
avoid short-range joint seams and silhouette streaks. Caster rasterization
uses constant and slope depth bias. Other receivers use a small depth bias.

Own pipelines/maps/descriptors retire through native submission completion.
Pipeline eviction uses the actual open submission serial and settled serial.
Turning Off destroys enhancement resources after the normal renderer finish;
no additional queue/device idle waits or independent completion clocks exist.
CPU camera hooks detach before their queue's host storage can be freed,
including renderer teardown and failed activation.

Scope and current limits

- Primary 640/720 by 480 logical targets, fixed-function depth-tested and
  depth-writing triangles/strips; includes explicit/remainder palette weights.
- Stage-0 2D cutouts use native UV/texture transforms, native comparison/ref
  and mip zero. Unsupported texgen, depth-replacing shaders, missing required
  array inputs, programmable vertices, blending and reflection targets are
  excluded. This is not a general replacement for the game's material logic.
- Original blob/planar shadows remain. There is no original-shadow suppression,
  offscreen-caster culling patch, OpenGL implementation or calibrated dynamic
  opacity. Added opacity is currently 0.4. Unsupported scenes retain original
  rendering. This can differ from the D3D11 native-port experiment.
- Retail validation covers the attract sequence and its scene transitions,
  not a complete playthrough, every venue or every GPU driver.

Validation

A full Windows UCRT64 core build and private retail Vulkan attract run passed.
The 1,800-frame run exercised camera transitions, On/Off/On and state restore.
Separate reload/reset/unload and modified-build rejection tests passed.
Khronos validation reported zero errors after correcting sampler passing,
unused caster inputs and complete prototype push-constant ranges. Additional
live captures ran with synchronization validation requested. OpenGL never
registered the option. Off's two captured checkpoints and aggregate video
hash matched the libretro baseline exactly. Ordinary draw entry/helper
instruction and call counts were unchanged; relocation addresses and assert
source locations differ after extracting the shared stream implementation.
Audio cadence has the same one-sample checkpoint phase offset as baseline;
audio is not claimed bit-exact across runs.

Standalone GPU tests with Khronos validation enabled and zero errors:
  96 rigid caster cases, 81,696 depth pixels;
  511 material/capture cases, 434,861 depth pixels;
  2,160 receiver cases, 1,838,160 RGBA pixels;
  source replacement, overwritten host packets and partial-record retirement.
CPU tests cover 8,193 code mutations, malformed headers, camera fits,
RAM-only reads, identity lifecycle, ordered capture, leases, 10,000 FIFO ring
laps and 60 option API/language/availability transitions. Existing streaming,
copy-on-write, texture ordering and query-scope regressions also pass.
